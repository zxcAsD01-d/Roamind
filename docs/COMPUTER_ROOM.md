# 电脑房与电脑交互

第四间卧室（原 `bedroom4`）改为电脑房，保留房间 ID 以兼容现有任务。新增书桌、椅子、显示器、主机、键盘、鼠标和储物柜；显示器运行本地接球小游戏，显示时间、分数。

```mermaid
flowchart LR
  V[YOLO 键盘与椅子] --> D[同帧实测双目表面]
  D --> N[键盘节点 + 邻近座面]
  N --> P[视觉路径接近桌前座椅]
  P --> S[坐稳并按自身骨长前倾]
  S --> K[双掌触键盘并看向显示器]
  K --> G[读取屏幕像素并提交方向键]
  G --> R[输入次数 / 时长 / 得分回执]
  R --> E[平滑收手保持坐姿]
```

## 使用

在网页“视觉物体 · 自动交互选项”中选择视觉识别到的键盘，满足键盘实测表面、附近新鲜座椅节点与自身标定后，“坐下玩电脑”才可用。默认使用 30 秒，结束后收手并保持坐稳，点击“起身”继续移动。“停止 / 取消”可中断并平滑收手。

高层 HTTP / MCP 沿用 `submit_agent_intent`：

```json
{"requestId":"computer-1","intent":{"kind":"interact","objectId":"视觉目录中的键盘ID","operation":"play_computer","duration":30,"timeout":180}}
```

时长范围 5–120 秒，timeout 至少比 duration 多 10 秒。`get_agent_context.execution.interaction.computer` 返回 `active/elapsed/inputs/score/completed`。只有坐稳、真实产生输入、持续到指定时长并收手，才确认成功；动画结束本身不算成功。

无聊超过 55 且精力允许时，自主行为优先尝试可用电脑，再考虑拿取。正在玩电脑时每秒精力消耗约 0.025、无聊下降约 0.4；不同时计算坐姿恢复。疲劳仍优先坐卧休息。

## 范围

正式规划只使用视觉节点和视觉地图。场景几何只负责执行时的支撑、穿入校验和唯一电脑实体匹配。小游戏控制器读取自身屏幕画布像素寻找目标，提交按键，按键需有双掌接触。它是本地屏幕小游戏适配器，尚未支持任意软件、操作系统、浏览器、文字输入或鼠标操作；不是通用视觉游戏智能体。

测试输出在 `output/playwright/computer-room/`。`browser-computer.js` 和 `browser-computer-controls.js` 是明确测试摆位和给定节点的实际 Wolferia 执行器验收，不能代替自主发现、导航和识别的端到端验收。

本轮验收：400 项 Python 测试、构建、真实 Wolferia 执行器与取消/起身测试通过。12 秒测试游戏产生 90 次按键、获得 5 分。真实视觉自动发现测试未通过：感知服务重启后仍繁忙，尚未产生可用键盘与座椅组合节点；因此不能宣称自动探索到电脑并玩游戏的完整链路已稳定。
