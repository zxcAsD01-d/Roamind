# 环境与具身行为内核

## 本轮实现

- 取消世界内漂浮房间标签；房间名保留在目的地下拉列表。
- 房屋采用 310 个共享实体部件：独立桌腿/桌面、座椅、沙发靠背与坐垫、床架/床垫/枕头、柜门把手、电视、卫浴和外窗。可见家具用共享圆角几何和实例批次绘制。
- 纹理以世界米制坐标映射，保留墙面多尺度视觉特征。新增织物、地毯、踢脚线、窗框、灯具、暖色局部光和一张 2048² 太阳阴影图。局部灯不生成多份阴影图。
- 实体几何供前端执行碰撞与后端碰撞复检共用；装饰织物和微小倒角不属于精确三角网格碰撞。
- 前端站立身体半径从 VRM 肩宽/髋宽测量，保留骨段体积；圆形边界与矩形障碍精确求距，连续扫描使用线段至矩形距离，避免方形膨胀角和采样漏过薄墙。
- 触摸手部半径统一为 3.5 cm，检测按球体到盒的距离计算；不再因为统一 4.5–5.5 cm 膨胀而拒绝正确表面接触。穿透仍拒绝。
- 物体接近使用自身臂长、肩高、肩偏移和视觉目标高度，计算站姿可达范围；在已知可通行格内寻找细粒度落脚点，并使用更精确的末段目标。没有真值导航回退。

## 环境驱动循环

`视觉记忆 → 保持当前目标 → 执行动作 → 实际反馈 → 冷却/失败退避 → 下一目标`

网页开启“自主生活 · 探索与社交”后，后端随网页心跳运行：

1. 已有任务继续执行，不被每帧的新候选替换。
2. 有新鲜人物机会时，调用现有视觉探索、接近、面向和挥手流程。
3. 暂无人物时，可以观察附近新物体；每个物体冷却 60 秒。
4. 社交完成后，同一人物冷却 90 秒，并继续探索其他机会。
5. 任务失败采用有上限的指数退避；事件和请求历史均有容量限制。
6. 直接控制/新高层目标暂停自主模式；关闭自主模式仅取消它拥有的任务。

这是脚本规划与视觉记忆内核，未训练新的神经行为模型。无自动云端 LLM 调用。

## 高层 LLM / MCP

- `get_agent_context(client_id?)`：视觉位姿、人物、空间记忆、物体交互候选、自身标定、执行结果与能力说明。
- `submit_agent_intent(request_id, intent, client_id?)`：提交 `socialize/navigate/inspect/interact/contact/action/face`。
- `set_agent_autonomy(enabled, client_id?)`：启停环境驱动循环。
- `get_character_goal` / `cancel_character_goal`：查询实际结果或取消。

HTTP 对应：

```text
GET  /api/agent/capabilities
POST /api/agent/context
POST /api/agent/intent
POST /api/agent/autonomy
```

示例请求：

```json
{
  "requestId": "conversation-42-goal-1",
  "intent": {"kind": "socialize", "timeout": 180}
}
```

```json
{
  "requestId": "conversation-42-goal-2",
  "intent": {"kind": "interact", "objectId": "从视觉候选读取", "operation": "touch"}
}
```

同一请求重试复用 requestId；不会再次中断或排队。相同 ID 的不同目标会报错。一个会话保存最近 32 个请求。多网页同时在线时应明确 clientId。

`navigate.position` 必须是视觉里程计坐标。`contact.targetId` 必须是视觉标注令牌。旧 `inspect_environment` 与房间导航是调试真值工具，不能当作角色看到的世界。

## 验证与边界

详细证据位于 `output/environment-upgrade/`。

- TypeScript/Vite 构建通过；完整 Python 回归 366 项通过。
- MCP 成功加载 43 项工具，包括三个高层接口。
- 真实浏览器检测：0 个漂浮 Sprite、12 个家具/墙体实例绘制批次（另有 1 个合并踢脚线批次）、310 个实体（不含角色、地板和装饰的其他 draw calls）；LLM 挥手指令实际完成，重试未重复执行。
- 约 46 秒自主运行：最大位移约 4 米，保持同一探索目标；窗边碰撞后重规划。活动帧率中位数约 30 fps，最低采样约 25 fps，无 pageerror。
- 接触检测单元回归：正确表面接触通过，向内穿透 1 cm 被拒绝；手/脚/头的局部跟踪与支撑检查通过。此证据是合成骨架，不等同于所有真实 VRM 接触已验证。
- 原 `src/retarget.ts` SHA256 保持 `bb6af52df769c6ed37a24e5391b82ba634741e27a647a26e57425367d2c997aa`。

当前仍是运动学仿真：未实现抓握力、承重、完整刚体动力学、任意姿态的全身接触规划或游戏文本输入。超出站姿可达范围会明确反馈，不能用拖动根节点伪装触摸。规划选项成立不表示物体业务操作成功，必须检查实际反馈。

追加实测：真实双目人物任务在约 46.5 秒内完成“接近 → 停稳 → 挥手”，过程中一次电视柜碰撞触发重规划，随后人物持续确认接管出口路线，保留同一任务。记录见 `social-result.txt`。

感知服务容量不足仍可能返回 HTTP 429。视觉循环对这类响应使用 120–800 ms 有界退避和小幅随机错峰，下一轮采集新帧；不会重传过期图像或重试触摸等有副作用的请求。429 本身不等于脚本异常，也不应被隐藏成成功。

真实标注触摸补测：两次测试板选点均在定位阶段返回“关键点周围双目深度不足”，未进入动作生成，因此本轮没有端到端触摸成功证据。保留 contact-result.txt、contact-retry.txt 和 contact-selection.png，不以合成骨架测试替代实际接触验收。

120 秒持续运行结果（最终版本）：60 个采样，累计位移约 21.97 m、最大离起点 3.92 m；始终只有 1 个探索任务，控制请求未出现异常。帧率中位数 30.00 fps、最低采样 22.48 fps；视觉可通行格 87 → 544。最后一次续接准备被拒绝时，当前动作继续完成。此结果证明持续运行与记忆增长，**不证明已经完成全屋探索**：仍存在局部绕行。报告见 `soak-report.json` 与 `soak-summary.json`。测试完成后自主模式关闭，三个服务保持在线。
